# データの保存先と経路検証

## データの保存先

駅・路線・グループは、プラグインのデータフォルダ内の **SQLite データベース**に保存されます。

```
plugins/AdvanceRailway/advancerailway.db
```

以前は `data/{stations,railways,groups}/<id>.json` というファイル群でしたが、現在この形式は使いません。
外部ツールからの取得・編集は [MineAuth HTTP API](/docs/mineauth-api) が担います
（旧 `ar file export` / `ar file import` コマンドは廃止されました）。

設定ファイル `config.json` は従来どおりファイルのままです。

## 旧データの自動取り込み

`data/` フォルダが残っていて、かつデータベースが空の場合、**起動時に一度だけ**自動で取り込みます。
取り込みが終わると `data/` は `data-backup-json-<数値>/` へリネームされ、以後は触りません。

取り込み時の扱い:

| 対象 | 扱い |
| --- | --- |
| ID | そのまま **slug** になります。主キーには新しく UUID が採番されます。 |
| 駅の色 | 未設定だった駅は、slug から導出した色を実体化して保存します（見た目は変わりません）。 |
| 路線（V2 形式） | 出発方角を `flags` の先頭に組み込んで自動変換します。 |
| 路線（V1 形式） | 分岐情報が無いため**取り込まれません**。該当する slug がサーバーログに警告として出ます。 |
| 駅ナンバリング | **取り込まれません**（下記）。 |

:::warning
**駅ナンバリングは移行されません。** ナンバリングの持ち主が駅からグループ（路線）へ変わったためです。
取り込み後、路線ごとに接頭辞と駅の並びを設定し直してください。

```
ar group set numbering-prefix <グループ> JY
ar group station set <グループ> <駅1> <駅2> <駅3> …
```

詳しくは [グループコマンド — 駅ナンバリング](/docs/commands/group#駅ナンバリング) を参照してください。
:::

### V1 路線の直し方

取り込まれなかった路線は、現地で
[`ar inspect`](/docs/commands/general#ar-inspect--線路の解析) を実行し、`[作成]` から
`flags` 付きの `ar railway add` で作り直してください。

## ar railway check — 経路の検証

```
ar railway check [--group <groupId>] [--station <stationId>]
```

保存されている開始点と `flags` から経路を再トレースし、保存済みの経路と一致するかを確認します。
レールの撤去や引き直しで実際の線路が変わってしまった路線を見つけられます。

絞り込みフラグ（両方指定した場合は AND）:

- `--group <groupId>`（短縮: `-g`） — 指定グループに属する路線だけを検証します。
- `--station <stationId>`（短縮: `-s`） — 指定駅に接続している路線だけを検証します。

### 最終確認時刻

検証に**成功した**路線には、そのときの時刻が最終確認時刻として記録されます。
`ar railway info` で確認でき、API でも `lastCheckedAt` として取得できます。

失敗した路線は更新しないので、前回成功したときの時刻が残ります。
これにより「いつから経路が確認できていないか」がそのまま読み取れます。一度も成功していない路線は「未確認」です。

### 報告される問題

| 表示 | 意味 |
| --- | --- |
| 再トレース失敗 | 経路をたどれませんでした。レールが撤去・変更された可能性があります。 |
| 経路変化 | 再トレースはできましたが、経路が保存時と一致しません。 |

いずれも `[TP]` リンクで始点駅に飛んで現地を確認し、`ar railway add` で引き直せば解消できます。

:::note
再トレースは未ロードのチャンクを同期ロードすることがあり、路線数が多いとサーバーに負荷がかかります。
このため起動時の自動検証は行わず、コマンドでの手動実行のみとしています。実行タイミングに注意してください。
:::
