# データ移行と経路検証

路線データを最新の形式に保ち、実際の線路と食い違っていないかを確認するためのコマンドが 2 つあります。
どちらも `advancerailway.railway.manage` 権限（OP）が必要です。

- `ar railway migrate` — 旧形式（V1/V2）の路線データを現行の **V3** に一括移行します。
- `ar railway check` — V3 路線の経路を再トレースし、保存時から変わっていないか検証します。

## 路線データの 3 つの形式

| 形式 | 状態 | 特徴 |
| --- | --- | --- |
| V1 | 旧形式 | 分岐情報を持ちません。 |
| V2 | 旧形式 | 分岐フラグを持ちますが、出発方向を隣接レール座標（directionPoint）で表します。 |
| V3 | **現行形式** | 出発方角を組み込んだ `flags` 文字列（例: `"EE"`）だけで経路を再現・検証できます。 |

`ar railway add` で作られる路線は常に V3 です。以前のバージョンで作った路線が残っている場合のみ、
移行が必要になります。

## ar railway migrate — V3 への一括移行

```
ar railway migrate
```

データフォルダ内のすべての路線を調べ、形式ごとに次のように処理します。

- **すでに V3** — 何もせずスキップします。
- **V2** — directionPoint を出発方角に変換して `flags` に組み込むだけなので、再トレースなしで確実に移行できます。
- **V1** — 分岐情報がないため、出発方角のみで経路を再トレースして移行します。
  途中に分岐（ポイント）がある路線は再トレースできず、**失敗として報告されます**。

実行後、「移行 / スキップ / 失敗」の件数が表示されます。

### 移行に失敗した路線の直し方

失敗行には始点駅への `[TP]` リンクが付くので、現地に飛んで
[`ar inspect`](/docs/commands/general#ar-inspect--線路の解析) を実行し、`[作成]` から
`flags` 付きの `ar railway add` で引き直してください。既存の路線 ID をそのまま指定すれば、
グループ・種別の設定を維持したまま V3 で上書きされます。

## ar railway check — 経路の検証

```
ar railway check [--group <groupId>] [--station <stationId>]
```

V3 路線を開始点＋ `flags` から再トレースし、保存されている経路と一致するかを確認します。
レールの撤去や引き直しで実際の線路が変わってしまった路線を見つけられます。

絞り込みフラグ（両方指定した場合は AND）:

- `--group <groupId>`（短縮: `-g`） — 指定グループに属する路線だけを検証します。
- `--station <stationId>`（短縮: `-s`） — 指定駅に接続している路線だけを検証します。

### 報告される問題

| 表示 | 意味 |
| --- | --- |
| 再トレース失敗 | 経路をたどれませんでした。レールが撤去・変更された可能性があります。 |
| 経路変化 | 再トレースはできましたが、経路が保存時と一致しません。 |

いずれも `[TP]` リンクで始点駅に飛んで現地を確認し、`ar railway add` で引き直せば解消できます。

:::note
再トレースは未ロードのチャンクを同期ロードすることがあり、路線数が多いとサーバーに負荷がかかります。
このため起動時の自動検証は行わず、コマンドでの手動実行のみとしています。実行タイミングに注意してください。
:::

:::note
`check` の対象は V3 のみです。旧形式の路線が残っている場合は、先に `ar railway migrate` を実行してください。
:::
